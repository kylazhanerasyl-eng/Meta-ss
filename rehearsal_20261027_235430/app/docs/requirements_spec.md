# ТРЕБОВАНИЯ К СИСТЕМЕ (REQUIREMENTS SPECIFICATION)

## 1. Функциональные требования по ролям пользователей

| Роль | Функциональные требования |
|---|---|
| **Студент (student)** | 1. Просмотр каталога тем с паспортом каждой темы (сложность, датасет, стек, опыт прошлых лет).<br>2. Формирование списка приоритетов (ранжирование тем от 1 до 5).<br>3. Подача заявки с мотивационной анкетой.<br>4. Предложение инициативной темы с проверкой антидубликата и авто-генерацией формулировки по ГОСТу через AI.<br>5. Отслеживание графика контрольных точек диплома.<br>6. Формирование печатной формы заявления (PDF/HTML). |
| **Научный руководитель (teacher)** | 1. Контроль заполнения квоты закрепленных студентов.<br>2. Просмотр входящих заявок с мотивацией и GPA претендентов.<br>3. Одобрение или аргументированное отклонение заявки.<br>4. Автоматическая передача отклоненного студента на его запасной приоритет. |
| **Заведующий кафедрой (head)** | 1. Обзор аналитических дашбордов (распределение по направлениям, загрузка ППС).<br>2. Мониторинг «светофора» загрузки преподавателей.<br>3. Выявление рисков (зависшие заявки >3 дней, студенты без темы).<br>4. Запуск алгоритма автоматического распределения Гейла–Шепли с протоколом решений.<br>5. Массовое утверждение тем приказом.<br>6. Экспорт официального приказа в формате CSV/Excel. |
| **Индустриальный партнер (company)** | 1. Публикация производственных кейсов и тем на бирже.<br>2. Просмотр откликнувшихся студентов с их GPA и технологическим стеком. |

---

## 2. Нефункциональные требования

- **Производительность:** Время отклика любого API эндпоинта не более 150 мс при 100 одновременных пользователях.
- **Безопасность:** Запрет открытого хранения паролей, использование SHA-256 с солью, журнал аудита событий комиссии.
- **Адаптивность:** Полная поддержка мобильных устройств и планшетов (Tailwind responsive grid).
- **Отказоустойчивость:** Автономность работы без внешних платных AI API (встроенный эвристический генератор ГОСТ).
